# Countrivo — App Reality Map

## 1. Honest summary

Countrivo is a **genuinely shipped, unusually complete** geography gaming platform: a Next.js 16 / React 19 / TypeScript / Tailwind v4 / Supabase web app that is **also wrapped as a native iOS app via Capacitor**, loading the live `countrivo.com` site inside an app-bound, locked-down WKWebView (so the website UI and the app UI are literally the same surface). The core is real and works: **14 game engines** (all present as pure logic + `useReducer` boards + landing/play routes + registry entries), a **deterministic Europe/Berlin daily-seed system** with admin re-roll editions, **versioned in-progress resume**, **server-side anti-cheat** (auth + score-sanity + per-game validation + seed re-computation for Country Draft & Stat Guesser + too-fast rejection), a **full social layer** (friends, invite links, friends/global leaderboards, head-to-head, challenges), **accounts** (email+password instant login, native Sign in with Apple with proper nonce hashing, password reset, profanity-filtered random geo-handles, JWT-verified account deletion), **243-country content** with 21 ranked stats, country/category/list pages, and a **broad SEO + share layer**. The native layer is real (haptics, status bar, splash, safe-area, session mirroring). **Completeness is high but not submission-ready**: a handful of features are **claimed-but-non-functional** (the Atlas/album sticker collection has *no write path or table migration anywhere in the repo*; the JS-side offline detector is wired but its callback is never passed; push deep-linking can't fire because no caller sets `gameSlug`), several descriptions are **inflated vs. the code** (Population Sort is advertised as drag-and-drop but is ▲/▼ buttons; the "progress ring" is a bar; "guests-only" lockout actually applies to everyone), and there are **two hard Apple-submission blockers** (store screenshots are the wrong resolution, and Sign in with Apple token revocation on account deletion is unimplemented — flagged by the team's own packet).

## 3. Consolidated, severity-ranked bugs & risks (for the fix phase)

### CRITICAL / submission-blocking
1. **Atlas sticker collection has no write path or table** — `src/app/album/page.tsx:50` reads `atlas_stickers`, but there is no CREATE TABLE migration, no server action, no DB trigger, and no RPC that ever writes a sticker (verified: only one `atlas_stickers` reference in the whole repo). `submitGameRun` never stamps. Feature shows 0 for every user. Either ship the write path (table + trigger/RPC on game completion) or hide the feature.
2. **Store screenshots are the wrong resolution** — `resources/store-screenshots/*.png` are 1290×2796; `docs/APP-STORE-SUBMISSION.txt:153` requires 1320×2868 for the 6.9-inch slot. App Store Connect rejects mismatched sizes. Regenerate before submission.
3. **Sign in with Apple token revocation not implemented on account deletion** — `supabase/functions/delete-account/index.ts` deletes the user but does not revoke the Apple refresh token. Apple Guideline 5.1.1(v) requires it; the team's own packet (`APP-STORE-SUBMISSION.txt:11-21`) flags this as a known rejection risk.

### HIGH
4. **`validateGameResult` default rejects unknown games** — `src/app/actions/game-runs.ts:528-529` returns `"unvalidated_game"` for any slug not cased; **blitz, borderline, supremacy** are absent from the validator switch (448-535). No live breakage today (those 3 are practice-only and never call `submitGameRun`), but the moment any gains persistence/leaderboards, every submit silently fails. Change default to `null` + log, or add explicit cases.

### MEDIUM
5. **Server streak uses UTC, app uses Berlin** — `game-runs.ts:399-424` walks dates with `setUTCDate` on a Berlin-derived `dateKey`; near the Berlin↔UTC boundary this can manufacture a gap and zero a valid streak. Compute the cursor in Europe/Berlin to match `computeLocalStreak`.
6. **`completeChallenge` trusts a client `myRunId`** — `src/app/actions/challenges.ts:155-183` stores `myRunId` into `challenged_run_id` without verifying the run belongs to the authenticated user or matches the challenge's game/date. A user could pass another player's run_id to inflate a duel score. (`createChallenge` already looks the run up server-side; `completeChallenge` should too.)
7. **Native offline JS callback never wired** — `src/components/native/native-bootstrap.tsx:12` calls `bootstrapNative()` with no `onOffline`; the Network listener at `src/lib/native/bootstrap.ts:81-82` fires into nothing. Mid-session network drops are invisible to the JS layer; only the initial-load `errorPath` (offline.html) works. Pass a real `onOffline` handler that drives a banner/overlay.
8. **`stats.json` pulled into the client bundle** — `src/components/games/population-sort/sort-board.tsx:22` directly imports `@/data/stats.json` in a `"use client"` file, shipping the whole stats dataset to the browser and violating the loader rule. Route through `src/lib/data/loader.ts`.
9. **Demo-account password committed in plaintext** — `docs/APP-STORE-SUBMISSION.txt:122-123`. Rotate and move to a secret store.

### LOW
10. **Push deep-link can't fire** — `supabase/functions/send-push/index.ts:64` never sets `data.gameSlug`; client tap handler (`bootstrap.ts:93-94`) is correctly guarded by `if (slug)`, so the tap silently does nothing (no `/games/undefined/play` crash, but the advertised deep-routing is dead until callers pass `gameSlug`).
11. **Stale pending challenges inflate the badge** — no expiry path; `getPendingChallengeCount` (`challenges.ts:85-96`) counts without a date filter while the list (`:100-124`) filters by `>= today`. Badge can show challenges the user can no longer see.
12. **`rehydrateSession` JSON.parse unguarded** — `src/lib/native/session-fallback.ts:43` parses stored Preferences without try/catch; a corrupted blob throws into the outer catch, silently leaving the user signed out with no recovery path or log.
13. **Apple sign-in cancel → "network" error** — `auth-modal.tsx:176-201` maps a user cancellation to `errorKind:'network'` ("Connection lost"). Misleading copy.
14. **Country Draft share is off-brand** — `country-draft-grid.tsx:52,60` uses a date instead of `#<n>` and a bare `countrivo.com` that won't auto-link in iMessage/WhatsApp/Twitter. Align to `https://countrivo.com` + puzzle number.
15. **`country detail` page imports `borders.json` directly** — `src/app/countries/[slug]/page.tsx:16` bypasses the loader (server component, so lower impact than #8, but same rule).
16. **OAuth callback redirect is not allowlisted** — `auth/callback/route.ts:10-12`; low surface but a crafted `next` (e.g. backslash variants) is a theoretical open-redirect.
17. **`isDailyFinish` inferred from `!onPlayAgain`** — `game-over-screen.tsx:284` would treat a replay-less practice board as a daily, mis-triggering push prompt + chaining. Use an explicit `mode` prop.
18. **`getDailyChainInfo` off-by-one** — `game-over-screen.tsx:219-243`: the current slug is excluded from "next" but may already be counted in "completed", skewing the remaining count in the flush-timing edge case.
19. **Lockout screen rank flash** — `daily-lockout-guard.tsx:99` renders "Already played" with no rank/percentile until the async server fetch lands, with no loading state.
20. **Invite-link Copy can copy empty string pre-hydration** — `friends-client.tsx:280-296`: `inviteUrl` is `''` during SSR; clicking Copy before hydration writes empty text to clipboard.

## 4. UI/UX design observations (for the design phase)

- **Population Sort should actually support drag** (or at least touch-drag) to match the registry/FEATURES copy; ▲/▼ buttons are functional but less intuitive on mobile (`sort-board.tsx`).
- **Inconsistent "daily progress" visuals**: the home bar turns **green** when all-done (`daily-hero.tsx`) but the game-over chain bar stays **gold** and never greens (`game-over-screen.tsx:529-565`). Unify.
- **"Ready" gate is good UX** (Speed Flags) — extend the same pre-roll to Country Streak and Higher/Lower, which jump straight into play.
- **Public profile is a dead end for social growth**: today's dailies aren't links, no rank shown, and "Add as friend" routes to `/friends` instead of `/friends/add/{username}`. Given the explicit growth north-star, make these prominent CTAs with direct routes.
- **Current streak hidden at 0** (profile header + cards) — a 0/"last streak" indicator would distinguish fresh vs. broken streaks.
- **Header daily counter is `sm:`-only** (`header.tsx:111-116`) — phone users (the iOS target) never see X/total in the header, and the bottom tab bar doesn't surface it either.
- **Combined pending badge is ambiguous** — friend requests + challenges are summed into one number; split sub-counts would clarify.
- **Status-bar cold-launch flash in light mode** — config hardcodes DARK (light text); runtime corrects it, but there's a brief white-on-light moment. Consider a light default + runtime override.
- **offline.html is off-design-system** — `-apple-system` font + emoji, no Space Grotesk/tokens; Retry does a full navigation rather than `location.reload()`. Acceptable for the errorPath pattern but jarring mid-flow.
- **Country detail renders flag emoji, never the SVG** that exists in `public/flags/` — a missed visual upgrade.
- **Share UX inconsistency** — Country Draft shows its share card always-visible inline; other games gate it behind a "Share result" button. Copy+Share both shown on iOS where the native sheet already copies.
- **Per-game OG images don't exist** — every shared page gets the same generic site OG image; per-game/per-country images would help virality.
- **"Daily curiosity facts" pool is only 4 factoids** — expands repetition for daily users; grow the pool.
- **Bottom tab bar hides on any path containing `/play`** (substring match, `bottom-tab-bar.tsx:30`) — a future `/replay` or `/display` route would be hidden too; tighten the matcher.
- **Brand-font copy should be corrected** to "Inter (web) / SF Pro (iOS) + Space Grotesk display."
- **Two games share the ⚡ emoji** (Blitz and Speed Flags) — picker confusion.
- **Profile edit form lacks grouping** — Identity / Preferences / Danger-zone sections would scale better.

## 5. Most important gaps & surprises an outside reviewer (or Apple) would notice

1. **The Atlas/"collect all 243 countries" feature is a facade in this repo** — fully built UI and read path, **zero write mechanism** (no table migration, no stamping on game completion). To a reviewer it looks done; in reality every account shows 0%. This is the single biggest "claimed but not real" gap.
2. **Two concrete App Store rejection blockers** are present and one is self-flagged: wrong-resolution screenshots (1290×2796 vs required 1320×2868) and **no Apple token revocation on account deletion** (Guideline 5.1.1(v)).
3. **Native polish is wired but partially dead-ends**: the offline detector's callback is never passed, and push notification deep-linking literally cannot route because no caller sets `gameSlug`. Both "exist" in code but do nothing end-to-end.
4. **Documentation describes infrastructure that doesn't exist** — multiplayer rooms (`rooms.ts`, `game_rooms`, `use-multiplayer`) are referenced in `CLAUDE.md`/`supabase.md` but are entirely absent. A new contributor would chase ghosts.
5. **Several user-facing descriptions overstate the implementation** — Population Sort "drag-and-drop" (it's buttons), "progress ring" (it's a bar), "guests-only lockout" (it's everyone), Country Draft share parity (different format + non-clickable URL). Individually minor, collectively they erode trust in the spec.
6. **Timezone seam in streaks** — the app is meticulously Berlin-anchored everywhere except the **server** streak walk, which is UTC. This is the kind of off-by-one that produces sporadic, hard-to-reproduce "my streak reset!" complaints near midnight.
7. **A trust gap in `completeChallenge`** — every other mutation hardened against client-supplied run IDs, but this one stores a client `myRunId` unverified, leaving duel scores spoofable.
8. **Credentials hygiene** — a demo-account password is committed in plaintext in the submission packet.
